# @popcomputer/document-graph 0.6.0

v0.6.0 adds graph retrieval within a known population of targets.

## Why

An application often knows which targets are eligible before it searches, such
as agencies based in the brief's country. Filtering a globally ranked list
afterwards wastes the candidate budget: on a catalogue where most agencies are
elsewhere, a required location removed over half of the candidates, and
relevant in-country agencies ranked below the global cut never competed.
`searchWithin` could already scope a search, but only to the nodes one
relation away from a single document.

## Added

- `retrieval.within(targets, { maximumDocuments })` and
  `search(query, { within })`. Resolve the population once, then reuse it
  across searches, such as one per key phrase. Direct routes search the
  targets' own documents. Relation routes search only source documents related
  to a target, found through canonical topology. Every route passes its
  population to the search provider as a document-key target, so semantic and
  text candidates come only from eligible documents. A source related to
  several targets ranks only the in-scope ones.
- `InvalidSearchQuery` reason `scope_too_large`: a population above
  `maximumDocuments` fails instead of searching an arbitrary subset, so the
  caller can choose a fallback. `maximumDocuments` is at most
  `MAX_GRAPH_SEARCH_TARGET_DOCUMENT_KEYS` (10,000).
- PostgreSQL `approximateAboveDocuments` on approximate vector search, default
  1,000. Larger document-key scopes use the HNSW index with the key filter
  applied during the scan. Smaller ones keep exact exhaustive scoring, which is
  cheap at that size and avoids exhausting `maxScanTuples` on a very selective
  filter.

## Changed

- Under `vectorSearch: { mode: "approximate" }`, document-key scopes above
  `approximateAboveDocuments` now use the index instead of always scoring
  exhaustively. Exhaustive scoring reads every scoped embedding, which does not
  scale to a population of thousands of documents.

## Upgrade

No migration. Existing searches are unchanged unless they pass `within`, or use
approximate search with a document-key scope larger than 1,000 documents; set
`approximateAboveDocuments: 10_000` to keep such scopes exhaustive.

## Verification

- 269 unit tests; 282 with the PostgreSQL and pgvector 0.8.1 suites.
- The HNSW suite scopes 80 of 1,600 documents: below the threshold results
  match exhaustive scoring exactly; through the index every request fills with
  in-scope rows and recall is at least 90% of exhaustive.
